# 기출 근거 DB 기록하기

형식·값의 정의는 `kb/README.md` 가 기준이다. 먼저 읽는다.

## 진행 상황 보기
```
python -X utf8 kb/check_kb.py                 # 규정별 기록 수 / 전체 문항 수
python -X utf8 kb/work.py 운영규정             # 그 규정 문항 id 목록
```
기록하지 않은 문항 = 목록에서 `kb/annot/<규정>.json` 에 없는 id. 순서대로 진행한다.

## 한 묶음(4~6문항) 기록 절차
1. `python -X utf8 kb/work.py <규정> <시작> <개수>` — 문제·정답·해설·후보 조문.
2. 보기마다 근거 조문을 `--art` 로 읽고, 필요하면 `--find <규정> <낱말>` 로 찾는다. 별표는 `규정:별표N`.
3. `kb/annot/<규정>.json` 에 기록:
   - `quote` 는 원문을 **복사**한다(띄어쓰기 차이는 검사기가 무시). 여러 토막은 `…` 로 잇는다.
   - 틀린 보기는 `trap: {orig: 원문 낱말, alt: 문제에서 바뀐 말}` — `alt` 는 문제 글에 그대로 있어야 한다.
   - 지금 원문과 출제 당시가 다르면 `status: 개정차이` + `note` 에 무엇이 바뀌었는지.
   - 근거를 원문에서 찾을 수 없으면 `ok: null` + `why`, 문항 `status: 확인필요` 또는 `일부확인`. **추측해서 채우지 않는다.**
4. `python -X utf8 kb/check_kb.py` — 통과할 때까지 고친다.
5. 몇 묶음마다 커밋한다: `git add kb && git commit -m "기출 근거 DB: <규정> N/M"`.

## 판단 기준
- `form`: 문제의 발문으로 정한다(옳지 않은 것은? → 정오-틀린것, 몇 개인가 → 개수 …).
- `focus`: 보기들이 실제로 비튼 지점(주체를 바꿨으면 주체, 기간을 바꿨으면 기간·기한).
- `level`: 1 한 조문·낱말 그대로 / 2 여러 조·항, 숫자·주체 구분, 개수·조합 / 3 여러 규정·사례·계산·함정 2개 이상.
- 국제인도법처럼 조문 번호가 없는 규정은 `국제인도법:제6장 3)` 같은 키를 쓴다(`work.py --find` 로 확인).
