# 사례형 + 원문 빈칸 문제 만들기

문제 데이터는 `kb/study/cases.py` 의 `CASES` 에 **조문 키와 원문 구절만** 적는다. 원문 문장·인용·빈칸 낱말은 빌더가 원문에서 가져와 글자 그대로인지 검사한다(옮겨 적지 않는다 → 토큰·오탈자 감소).
앱 쪽은 `case-bl.js/.css`(빈칸 채점 화면), 묶음 `case`(기출·오답 탭의 "사례형·빈칸 · 직원운영규정").

## 시작 전에
1. `CLAUDE.md`, `exam-kb` 스킬의 규칙을 따른다(판단은 원문으로만, 학습 기록 읽기만).
2. **`kb/study/가채점오류.md` 를 읽는다** — 공식 답지와 어긋났던 판정 6건의 교훈(한정어·단위·연장 숫자·계산 기준일).
3. 이미 낸 사례 확인: `python -X utf8 kb/study/cases.py --coverage` (쓴 조문 / 안 쓴 조문). 안 쓴 조문과 아직 안 나온 주제를 우선한다.
4. 조문 원문은 필요한 것만: `python -X utf8 tools/kbq.py art 운영규정:45` (원문 + 그 조문의 기출 함정. 전체 규정·`exam_kb.json` 은 통독 금지 — 훅이 막는다). 사례 한 묶음을 넣고 나면 `python -X utf8 tools/kbq.py checkpoint "<한 줄>"`. 별표는 `운영규정:별표6` 처럼 읽는다. 누가 하는지가 걸리면 `kb/조직구조.md`.

## 사례형 만드는 법
- 한 직원의 인사기본사항(입사일=수습 시작일, 수습 종료일, **임용일**을 따로, 직종·계급·소속, 면허 취득일, 입사 전 경력, 경조사)을 필요한 만큼. 한 사례에 모든 주제를 억지로 넣지 않는다.
- 주제 후보: 연차 발생(근무한 달 ≠ 발생), 경력 환산(직렬별·자격증 전후·군 의무복무), 정기승급 발령권자(일반 임용권과 구별), 기관장·소속기관장·기관장급 구별, "~에도 불구하고" 예외, 경조휴가(휴일 산입·종료일), 사용 기한(시작 vs 마지막 날), 분할 사용(분할 횟수 vs 일수), 신규임용자과정(수습기간·임용일·수료 기한).
- **가~마를 하나씩 독립적으로 판정**해 O/X 와 정답 개수를 정한 뒤에 선택지를 맞춘다(선택지에 맞춰 해석하지 않는다). 사례끼리 정답 개수·정답 번호를 다르게.
- 각 보기(`stmts`)에 `text`, `v`(O/X), `quotes`[(조문키, 원문 인용, 표시용 조항)], `why`(판단 이유 — 직접 인용과 해석을 구별), `calc`(계산 과정), `trap`(함정)을 모두 쓴다. 틀린 보기는 원문의 숫자·주체·기준일·요건·예외 **하나만** 바꾼다.
- 적용 순서: 일반 규정 → 특별 규정(~에도 불구하고) → 예외·단서 → 별표 비고. 해설에 최종 근거를 밝힌다.
- 원문과 표현만 다르다고 오답으로 두지 않는다(사례·OX 는 의미·적용 결과로 판정). 낱말 일치는 원문 빈칸에만.

## 원문 빈칸 만드는 법 (사례당 5개)
`blanks` 한 항목 = 사례 보기 하나의 근거 문장 하나. `art`, `clause`(제N조 제N호 N목), `from`/`to`(문장 앞·뒤 구절 — 줄을 넘지 않게, 같은 구절이 앞에 또 있으면 더 길게), `blank`(빈칸 낱말들, 문장 순서대로), `tip`.
- 핵심 낱말·숫자·주체·기간·예외만 빈칸으로. 문장부호·괄호는 빈칸 밖(낱말에 넣지 않는다). 낱말은 원문 그대로 — 앱이 한 글자당 □ 로 보여 주고 동의어는 오답 처리한다.

## 반드시 피할 것 (이번에 정한 기준)
- **원문에 없는 해석은 문제로 내지 않는다.** 예: 연차가 '다음 달 1일'에 발생한다는 시점은 원문에 없어 쓰지 않고, 특정 시점(예: 10. 15. 현재)에서 몇 일 부여됐는지로 묻는다. "3회 분할"이 3조각인지 2번 분할인지는 모호해 O 보기는 3회, X 보기는 5회처럼 양쪽 해석에 같은 결과가 나오게.
- 경계일(30일째 등)이 갈리는 보기는 피한다. 날짜 계산은 경계에서 멀리.
- 경력 사례는 이전 직장 이름만 쓰지 말고 **경력종별·실제 직종/업무·자격증 취득일·군 의무복무 여부**를 모두 적는다. 별표 제6호 표 열 순서: 일반직원·특수경력직원·특정직원·전문직원·기술직원·기능직원·고용원(기타업무 환산율: 일반 50, 고용원 50, 나머지 '-').
- **휴가 날짜 계산은 근무일·휴일 조건을 사례에 쓴다**(근무일 월~금, 공휴일 없음 등). 해당 기간에 공휴일이 있으면 공식 달력으로 확인한 목록을 사례에 적는다. 계산은 손으로 하지 말고 `python -X utf8 kb/study/cases.py --cal 2026-11-11 5 [공휴일 YYYY-MM-DD …]` 로(제47조: 30일 미만이면 휴일 불산입, 30일 이상이면 산입).
- 공식 답지는 출제 의도 확인용. 원문과 충돌하면 차이를 밝히고 복제하지 않는다. 확정할 수 없는 것은 뺀다.

## 넣고 확인하기
1. `CASES` 맨 뒤에 새 사례를 **추가**한다(기존 id `case-N`, `case-N-bK` 는 학습 기록과 연결돼 있으므로 바꾸지 않는다. 기존 문항을 고쳐 정답이 바뀌면 사용자에게 알린다).
2. `python -X utf8 kb/study/cases.py` → 인용·빈칸 검사와 빈칸 문장 목록(눈으로 □ 위치 확인).
3. `python -X utf8 build_artifact.py`(검사 통과해야 빌드됨) → `site/` 서버(8765)에서 `node tests/case-test.mjs` 와 전체 테스트(PASS 만).
4. 화면 확인(태블릿·폰) → 게시·백업·커밋은 `artifact-release` 스킬(게시 전 게시본 비교).
5. 사용자가 푼 결과로 공식 답과 어긋나면 `가채점오류` 방식으로 기록해 교훈을 남긴다(`kb/study/답지.json` 규칙).
